# k8s-alert Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Go Kubernetes incident notifier with Pachca, optional Telegram and Helm.
**Architecture:** client-go informer caches feed a single decision loop. Independent bounded diagnostic and per-destination delivery workers; checkpoint incident/delivery state to a dedicated ConfigMap.
**Tech Stack:** Go 1.26, client-go, yaml.v3, Helm 3/4, Docker Buildx.
**Spec:** ../specs/2026-11-21-k8s-alert-design.md

## Global Constraints
- All original must-haves in first delivery; dev/prod presets; Job/CronJob descendants excluded when configured.
- No hot reload: Reloader named-resource annotations exclude state ConfigMap.
- Telegram disabled by default; no Secret requirement when disabled.
- Linux target OS; Docker TARGETARCH supports amd64 and arm64, independent of Mac host.
- One replica/Recreate; graceful checkpoint; no external DB or PVC.

## Review Focus
- Lost observation must not imply recovery.
- Workload replacement pods retain mute history; different containers do not collide.
- Webhook errors must not disclose credentials.
- Disabled destinations require no credential files.
- Checkpoint writes must not trigger Reloader.
